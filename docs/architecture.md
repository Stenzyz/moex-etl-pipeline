# Архитектура

![Архитектура](architecture.png)

Исходник диаграммы: `architecture.mmd`.

## Поток данных

1. Extract (`ingest/`, Python). Клиент ISS выкачивает минутные свечи по
   списку бумаг и кладёт их в S3 (MinIO) как parquet, один файл на бумагу и день.
2. Transform (`spark_jobs/`, Spark). Джобы отправляются из Airflow через
   spark-submit в отдельный Spark-кластер (master и worker). Spark читает raw,
   чистит, собирает таймфреймы 10м/1ч/1д, считает индикаторы и корреляции и
   пишет результат обратно в S3, в `processed/`.
3. Load (ClickHouse). ClickHouse сам забирает parquet из `processed/` через
   табличную функцию `s3()`: `INSERT INTO ... SELECT * FROM s3(...)`.
4. BI (Superset). Дашборд смотрит только в витрины, под read-only пользователем.

Airflow оркеструет всё: extract по расписанию, transform и load запускаются
через Asset после успешного extract.

## Слои

| Слой | Где | Что лежит | Кто пишет |
|---|---|---|---|
| raw | S3 `moex-lake/raw/candles/interval=1/secid=.../date=....parquet` | минутки как в ответе ISS, плюс `loaded_at` | `ingest` |
| processed | S3 `moex-lake/processed/...` | чистые свечи всех таймфреймов и витрины в parquet | Spark |
| core | ClickHouse `moex.candles` | свечи 1м/10м/1ч/1д, одна таблица с колонкой `interval` | ClickHouse из `processed/` |
| marts | ClickHouse `moex.mart_*` | агрегаты под конкретный вопрос дашборда | ClickHouse из `processed/` |

Почему Spark не пишет в ClickHouse напрямую. Для этого нужен JDBC-драйвер или
отдельный коннектор (ещё jar-ы под точные версии), и вставка идёт медленнее.
ClickHouse умеет читать parquet из S3 сам и делает это быстро, а Spark
остаётся со своей естественной задачей: читать и писать файлы. Заодно
`processed/` можно перезалить в ClickHouse без пересчёта Spark.

## Вопросы дашборда и витрины

| # | Вопрос | Витрина |
|---|---|---|
| 1 | Как двигалась цена бумаги на выбранном таймфрейме | `candles` (core) |
| 2 | Какие бумаги и сектора сейчас самые волатильные, как волатильность менялась во времени | `mart_indicators_daily` (доходность, SMA/EMA, волатильность за 20 дней) |
| 3 | Какие бумаги двигаются вместе, а какие независимо | `mart_correlation` (попарная корреляция дневных доходностей за окно) |
| 4 | Кто лидер по обороту в рублях за день/неделю/месяц, какая доля у сектора | `mart_turnover_daily` |
| 5 | Как распределены оборот и волатильность внутри дня по часам, сколько дают утренняя и вечерняя сессии | `mart_intraday_profile` |

Сектор бумаги берётся из `config/securities.csv`: ISS его не отдаёт в
удобном виде, а для 40 бумаг ручной справочник проще и надёжнее.

## Зачем каждый инструмент

- MinIO: S3-совместимое хранилище для raw и processed. Официальные образы
  MinIO в сентябре 2026 убрали с Docker Hub, поэтому используется сборка
  сообщества `pgsty/minio`. Код работает через S3 API (boto3, s3a, `s3()` в
  ClickHouse) и без изменений переезжает в облачный S3, меняются только
  адрес и ключи в `.env`.
- Spark: трансформации оконными функциями (почему Spark, см. `scope.md`).
  Отдельный кластер из master и одного worker, драйвер запускается из Airflow.
- ClickHouse: колоночное хранилище под тайм-серии, быстрые агрегаты по
  `(secid, ts)`, партиции по месяцу.
- Airflow: расписание, ретраи, зависимости между шагами.
- Superset: дашборд, есть драйвер ClickHouse.
- Postgres: только метабаза для Airflow и Superset, данные в нём не лежат.
